# Niche digest

The agent instructions say what to do each run. This guide fixes what counts as a good item and the issue layout.

## Source rules
- Start with the sources the user trusts, then search the niche for what they missed.
- Prefer the primary source: the company's changelog or blog, the paper, the release notes, the original post. Link a news write-up only when there is no primary source, and say so.
- Every item needs a publication date read from the page itself. If the page shows no date, or the date is older than seven days, leave the item out.
- Never use a source the user listed under "Leave out", and never reuse a link that memory shows in a past issue.
- Do not quote more than one short sentence from a source. Write the summary in your own words.
- "Why it matters" must be about the readers named in the inputs. If you cannot say why it matters to them, drop the item.
- If the week had fewer good items than asked for, send fewer and say so rather than filling the slots.

## Source note
Give each item one of these, with a few words on what its claims rest on:
- Primary source: the maker, the authors or the official record.
- Opinion: one person's view or analysis.
- Vendor marketing: a company describing its own product.
- News report: a write-up of someone else's announcement.

## Issue layout
```text
Subject: <subject line>

# <Issue title>, <yyyy-mm-dd>

<Intro paragraph in the user's voice>

## 1. <Item headline>
<Two-sentence summary.>
Why it matters: <one sentence for these readers>
Source: <link> (published <yyyy-mm-dd>). <Source note>

## 2. ...

## Sources with nothing this week
- <source>

## Sources I could not reach
- <site>: <reason>
```

## Memory
- Save each included link and the issue date, so the next issue skips them.
- When the user says in a session which items or topics their readers liked or skipped, record that in their words and weigh it when picking items. Never guess what readers liked.
